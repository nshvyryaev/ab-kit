# Спецификация ab-kit (версия алгоритма `ab:v1`)

Всё, что нужно, чтобы написать реализацию на другом языке, не читая JS.
Реализация считается совместимой, если проходит все векторы из
`vectors/bucketing.json` и ведёт себя по разделам «Назначение» и «Протокол».

## Конфиг экспериментов

Список объектов:

```json
[
  {
    "key": "onboarding-v2",
    "salt": "onboarding-v2-2026-10",
    "status": "running",
    "variants": [
      { "key": "control", "weight": 50 },
      { "key": "v2", "weight": 50 }
    ]
  }
]
```

| поле | правило |
|---|---|
| `key` | непустая строка, уникальна в списке |
| `salt` | непустая строка; своя у каждого эксперимента |
| `status` | `running` (по умолчанию), `paused` или `concluded` |
| `variants` | непустой массив; `key` — непустая строка, уникальна в эксперименте; `weight` — целое ≥ 0; сумма весов > 0 |
| `winner` | обязателен при `concluded` и должен быть ключом варианта; при других статусах запрещён |

Первый вариант — **контроль**. Конфиг с нарушением любого правила
отвергается целиком при загрузке, а не при первом назначении.

## Ведро

```
input  = "ab:v1:" + salt + ":" + unit          (строка, кодировка UTF-8)
digest = SHA-256(input)
bucket = (digest[0] << 24 | digest[1] << 16 | digest[2] << 8 | digest[3]) mod 10000
```

Первые четыре байта читаются как **беззнаковое** 32-битное целое старшим
байтом вперёд. В языках, где сдвиг даёт знаковое число, используйте 64-битную
арифметику. `salt` и `unit` берутся как есть: без обрезки пробелов, смены
регистра и нормализации Unicode.

## Вариант по ведру

Пусть веса `w[0..k-1]`, сумма `W`. Границы:

```
edge[i] = floor(10000 * (w[0] + … + w[i]) / W)   для i < k-1
edge[k-1] = 10000
```

Вариант — первый `i`, для которого `bucket < edge[i]` (строго меньше).
Вариант с весом 0 получает ту же границу, что предыдущий, и не выпадает
никогда.

## Назначение

`assign(experiment, unit, enroll)`, по порядку:

1. Эксперимента нет в конфиге → `{ variant: null, enrolled: false }`.
2. `concluded` → `{ variant: winner, enrolled: false }`; хранилище не трогается.
3. `unit` пустая или отсутствует → `{ variant: контроль, enrolled: false }`.
4. В хранилище есть запись `(experiment, unit)` → `{ variant: записанный,
   enrolled: true }`. Если записанного варианта больше нет в конфиге —
   контроль, запись не трогается.
5. Записи нет, `enroll` истинно и статус `running` → вариант по ведру;
   записать «вставить, если нет»; вернуть вариант **из хранилища после
   вставки** (при гонке побеждает первая запись) и `enrolled: true`.
6. Иначе → `{ variant: контроль, enrolled: false }`.

Ошибка хранилища на шагах 4–5 не выходит наружу:
`{ variant: контроль, enrolled: false, error: true }`.

Запись — `(experiment, unit, variant, assigned_at)`, `assigned_at` —
миллисекунды Unix. Уникальность — по паре `(experiment, unit)`.

## Хранилище

Четыре операции; любая БД, реализующая их, подходит:

| операция | смысл |
|---|---|
| `get(experiment, unit)` | запись `{ variant, assigned_at }` или пусто |
| `claim(record)` | вставить, если записи с этой парой нет; вернуть запись, лежащую после вставки |
| `count(experiment)` | `{ вариант: число записей }` |
| `close()` | освободить ресурсы |

`claim` обязан быть атомарным относительно других `claim` той же пары.

## Протокол

```
POST /v1/ab/assign
Content-Type: application/json

{ "experiments": ["onboarding-v2"], "enroll": ["onboarding-v2"], …поля хозяина }
```

| поле | правило |
|---|---|
| `experiments` | массив строк, не больше 20; повторы схлопываются |
| `enroll` | массив строк, по умолчанию пуст; ключи, которых нет в `experiments`, игнорируются |
| прочие поля | принадлежат хозяину (параметры запуска, анонимный id); реализация их не читает, их читает функция хозяина, определяющая единицу |

Ответ `200`:

```json
{ "assignments": { "onboarding-v2": { "variant": "v2", "enrolled": true } } }
```

По каждому ключу из `experiments` — результат `assign`. Поле `error: true`
присутствует, если назначение упало в хранилище.

Единицу определяет хозяин. Если она не определена (нет личности, функция
хозяина упала) — по каждому эксперименту контроль, `enrolled: false`, без
записи, ответ всё равно `200`.

Ответ `400` `{ "error": "<код>" }`:

| код | когда |
|---|---|
| `too_large` | тело больше 8192 байт |
| `json` | тело — не JSON |
| `body` | тело — не объект |
| `experiments` | `experiments` не массив строк |
| `too_many` | больше 20 экспериментов |
| `enroll` | `enroll` не массив |

`500` из-за реализации ab-kit не отвечается никогда: ручка живёт в процессе
хозяина, который может принимать деньги.

## Векторы

`vectors/bucketing.json` — `{ "algorithm": "ab:v1", "vectors": [...] }`.
Вектор с `salt` и `unit` проверяет ведро и вариант; вектор без них — только
выбор варианта по заданному ведру (граничные случаи «строго меньше»).

```json
{"salt":"…","unit":"…","weights":[50,50],"boundaries":[5000,10000],"bucket":7181,"variant":1}
{"weights":[50,50],"boundaries":[5000,10000],"bucket":5000,"variant":1}
```

`variant` — индекс в массиве весов. Векторы пересобираются только вместе с
осознанной сменой алгоритма и версии в префиксе `ab:vN:`.
