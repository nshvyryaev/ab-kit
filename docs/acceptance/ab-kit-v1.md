# ab-kit v1: назначение, закрепление, запись, ручка, клиент и сравнение долей

Запрос инженера: «сделаем на платформе возможность запуска AB теста на
пользователях: половине будем показывать старое обучение, половине — новое.
За пару дней сравним метрики… Систему AB делай простую. Лучше всего — в
отдельном проекте… Сейчас сделай ее интегрируемой с сервером нашей нынешней
игры. В будущем не исключена вероятность, что там же будет лежать ее копия на
другом языке. Заложи в структуру папок проекта возможность добавить другой
язык. А в код — возможность подмены БД».

Ответы инженера: встраивается пакетом, как analytics-kit; эксперименты —
конфигом в коде хозяина; в эксперимент попадают только новые. Дизайн —
`docs/design.md`.

Встраивание в игру — отдельные критерии в репозитории игры, здесь только
пакет.

## Критерии

### Алгоритм и спецификация

- [check] `spec/README.md` описывает алгоритм назначения, формат конфига и
  протокол `POST /v1/ab/assign` так, что по нему можно написать реализацию на
  другом языке, не читая JS
- [check] `spec/vectors/` — не меньше 50 тестовых векторов (соль, единица,
  веса → ведро и вариант), в том числе кириллица в единице, три варианта,
  неравные веса, вес 0; JS-реализация проходит их все (`npm test`)
- [check] Распределение честное: на 100 000 случайных единиц доля каждого
  варианта при весах 50/50 и 10/90 отклоняется от заданной не больше чем на
  1 процентный пункт; разбиения двух экспериментов с разной солью не
  совпадают (доля совпавших назначений около 50%, а не около 100%)

### Назначение

- [check] Одна и та же единица в одном эксперименте всегда получает один и
  тот же вариант — и повторным вызовом, и после пересоздания хранилища на том
  же файле
- [check] Записанный вариант не меняется при смене весов в конфиге
- [check] Без `enroll` новая единица получает контроль, `enrolled: false`, и
  ничего не записывается
- [check] `paused`: новых не записывает (контроль, `enrolled: false`),
  записанные получают свой вариант; `concluded`: все, записанные тоже,
  получают `winner`
- [check] Две одновременные попытки записать одну единицу дают одну запись и
  один вариант у обоих вызовов
- [check] Конфиг с ошибкой (нет вариантов, отрицательный или нецелый вес,
  `winner` не из вариантов, повтор ключа, пустая соль) отвергается при
  создании, а не при первом назначении
- [check] Ошибка хранилища не выходит наружу: `assign` возвращает контроль,
  `enrolled: false`, `error: true`

### Хранилище

- [check] Интерфейс хранилища описан в `docs/design.md`; реализации SQLite
  (`node:sqlite`) и память проходят один общий набор контрактных тестов,
  экспортируемый пакетом (`runStoreContract`)
- [check] Пакет без зависимостей: в `package.json` нет `dependencies`

### Сервер

- [check] `createAbHandler({ experiments, store, resolveUnit })` отвечает на
  `POST /v1/ab/assign` по протоколу из `spec/README.md`; единицу определяет
  только `resolveUnit` хозяина
- [check] `resolveUnit` вернул пусто — по каждому эксперименту контроль,
  `enrolled: false`, без записи; ответ 200
- [check] Неизвестный эксперимент в запросе — `variant: null`; больше 20
  экспериментов в запросе или тело больше 8 КБ — ответ 400; ручка никогда не
  отвечает 500 из-за ab-kit

### Клиент

- [check] `createAbClient({ endpoint, storage, timeoutMs })` возвращает
  варианты; при таймауте или ошибке сети — последний сохранённый ответ, а без
  него — контроль; исключений наружу не бросает
- [check] Браузерная часть — не больше 1,5 КБ в gzip по минифицированному
  коду

### Статистика

- [check] `compareProportions({ a: { n, x }, b: { n, x } })` возвращает
  доли, разницу, 95% доверительный интервал разницы и двустороннее
  p-значение; на эталонных примерах совпадает с расчётом вручную до третьего
  знака
- [check] `sampleSize({ p, mde })` для 10% → 15% даёт 680 ± 5 на вариант при
  α = 0,05 и мощности 80%

### Проверки

- [check] `npm test` выходит с нулём
